## Sections to populate
- **I. IDENTITY** — Node ID (`CISEM-{TYPE}-{SEQ}` via naming-registry.yaml, ARCH-00011), Node type/TYPE prefix, Short description (human + AI), Status, Version + Change protocol
- **II. GOAL & PURPOSE** — Goal incl. measurable outcome, Role, Who I am serving
- **III. POSITION IN THE ARCHITECTURE** — Position in schema (T-SYS/T-DOM), Position in corespine, Position in pipeline(s), Connection to Threshold
- **IV. RELATIONSHIPS** — Who I inherit from / obligated by, Who inherits from me / I deliver to, Dependencies, Propagation membership
- **V. GOVERNANCE / VOCABULARY / NAMING** — Vocabulary alignment (VOC-00001), Naming/numbering compliance (VOC-00002 status enum), Tags, Statuses (incl. internal)
- **VI. AI BEHAVIOR / POCKET** — Pocket Declaration (reasoning_scope, inherited_constraints, output_contract, ai_cannot), Path Rejection Declaration
- **VII. STRUCTURE / SIZE GOVERNANCE** — Length/complexity compliance (3,500 words / 200 lines, §3.6), Mini-tree split protocol, Mandatory depth levels
- **VIII. NOTIFICATION / MONITORING** — What I notify, How I stay updated
- **IX. IMPROVEMENT / EVOLUTION** — Improvement loop membership, Wisdom-entry hook, Verification scenario + last_verified + owner
- **X. AUDIT** — Applicable checklist reference, Gate Trace (§3.0–3.7, run-by/when/result), Change log
- ARCH-00230 checklist cross-check — Governing corespine named/"none yet"+reason, "Why this exists", the rule/content itself, "Does NOT cover", Self-compliance note, INHERITANCE declaration

## Notes
Use this template for any governed node whose TYPE does not have a more specific template in this directory (i.e. not a corespine manifest, protocol, wizard, plan, skill, agent, check, IBD entry, archive entry, vocabulary node, or founding node) — duplicate + declare `core_template: node-generic-template` + `disabled_capabilities:` + its own name/tag/status (ARCH-00408).
