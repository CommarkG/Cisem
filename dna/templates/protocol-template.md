## Sections to populate
- Node ID, Type (ARCH, or a registered protocol-type prefix), Status, depth_level, tags — header complete (ARCH-00230 line 1)
- Goal — stated, one sentence, what this protocol governs (ARCH-00230 line 2)
- Governing corespine — named, or explicit "none yet" with reason (ARCH-00230 line 3)
- "Why this exists" — full reasoning, standalone, no assumed context (ARCH-00230 line 4)
- The rule itself — stated as an executable procedure, not prose (ARCH-00230 line 5)
- Explicit "Does NOT cover" section — scope boundary named (ARCH-00230 line 6)
- Self-compliance note, applied to this document itself (ARCH-00230 line 7)
- Role, Who-serving, Pocket Declaration — present OR explicitly marked N/A (ARCH-00230 line 8)
- INHERITANCE — declares its parent (corespine/element) and inherits the parent's WHAT as testable assertions; carries the persona SSOT reference (never copy), the governing corespine, and this checklist (ARCH-00230 INHERITANCE clause)
- Node DNA Sections III–IV (Position in schema/corespine/pipeline; Relationships — inherit-from / deliver-to / dependencies / propagation membership) — per ARCH-00008
- Node DNA Section VII (Structure/Size Governance — 3,500 words / 200 lines, §3.6 mini-tree split if exceeded)
- Node DNA Section IX (Improvement/Evolution — loop membership, verification scenario + last_verified + owner)
- Node DNA Section X (Audit — Gate Trace §3.0–3.7 run-by/when/result, Change log)
- CAL reference (CISEM-ARCH-00390) — which pre-commit/plan-audit checks this protocol feeds or is fed by

## Notes
An instance protocol is a duplicate of this template that declares `core_template: protocol-template` + any `disabled_capabilities:` and carries its own name/tag/status (ARCH-00408 core-template principle) — never a hand-forked variant of an existing protocol's scope.
