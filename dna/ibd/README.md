# IBD — Internal Brain Dump (raw parking lot)
Purpose: capture the Governor's raw thoughts/issues AS-IS for later processing,
WITHOUT the §3 creation gates — because forcing structure at capture-time buries
native vocabulary (the exact failure this prevents; see CLAUDE.md §2.5 D2 and IBD-0001).

## Protocol (standing behavior — CLAUDE.md §2.6)
1. **CAPTURE VERBATIM.** The raw body is never edited, restructured, summarized, or
   "optimized." Not one word. Native vocabulary is the payload, not noise.
2. **MINIMAL METADATA:** `IBD-NNNN`, a proposed tag, `status: PARKED-RAW`, captured date.
3. **PRESENT ONLY tag + status** to the Governor. Nothing else. No analysis, no reshaping.
4. **RATIFY OR SILENCE:** Governor ratifies/edits the tag, OR says nothing → saved as-is anyway.
5. **PROMOTION (separate, later):** an IBD entry may be promoted to a governed node, which
   THEN runs the full §3 gates and gets a real `CISEM-{TYPE}-{SEQ}` ID. Until then it is
   deliberately PRE-NODE and gate-exempt.

## Why this is DNA-compliant, not a gate-bypass
IBD is a NAMED, sanctioned exception (like WITNESS's Corespine-First exception).
Justification: D2 (guard boundaries, not paths) + the native-vocabulary trap —
premature optimization at capture IS the unwanted behavior. Capturing raw is the
correct path; structuring later is the governed path. Nothing is lost, nothing is
prematurely smoothed.

## Namespace
`IBD-NNNN` is a PRE-NODE parking id, OUTSIDE the CISEM-{TYPE}-{SEQ} node system — so it
does not touch the naming registry, and the plan-audit node-reference scan ignores it by
design. Promotion assigns a real node ID at that time.
