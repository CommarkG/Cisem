## 1. THE CONFLICT-RESOLUTION MODEL — Governor-APPROVED direction (2026-07-19; "1 three approved")
Not open-vs-rigid (open forest RULED-OUT-PERMANENT, DEC-0001). The design is a **SCALE**, not a static winner:

**Layer 1 — DEFAULT presumption (the floor).** Common-case conflicts resolve INSTANTLY + DETERMINISTICALLY by a
ratified default precedence. This is the guardrail against AI non-determinism/drift. "Sealed" here = "the current
ratified presumption," NOT "frozen." Without a floor, every conflict is a fresh deliberation = the drift we fight.

**Layer 2 — a SCALE that triages each conflict (Governor clarification 2026-07-19 — NOT "AI deliberates every conflict"):**
the scale decides WHEN the rigid default fires vs WHEN a conflict is vaulted. Bands:
  - **RIGID-DEFAULT fires** — trivial/known conflict → the ratified precedence applies, no deliberation.
  - **PROVISIONAL-PROCEED + PARK** — low-risk, resolvable now → AI resolves provisionally, proceeds immediately
    (progress), and PARKS the decision for ratification (respect). Never final until ratified.
  - **VAULT-AND-HALT** — hard/fundamental clash → the platform STOPS and says, humbly, *"we have an internal
    conflict; something fundamental is clashing — we'll get back to you."* Vaulted for reconciliation (→ archive
    VAULTED-CONFLICT, e.g. DEC-0004). **Applies to BOTH internal development AND external apps/solutions built on
    CISEM** — a deployed solution hitting an internal governance conflict degrades gracefully ("internal conflict,
    we'll get back to you") instead of forcing a wrong answer. Risk-tiered: high-risk/hard → halt; never proceed provisionally.

**Layer 3 — the LEARNING LOOP (evolve the DNA from lived conflict).** Every conflict + its resolution + its
ratification is DATA. Recurring conflicts → the RQC PROPOSES codifying: NARROW where a gap was found, or EXPAND a
rule (Governor's own example: "no governed creation without a ratified plan" → "…unless it clears the SWIFT gates").
**Propose-then-ratify, NEVER self-enact** (D5 + A4) — self-evolution that self-ratifies is the runaway case.

**Existing-First:** almost all of this is COMPOSITION of existing machinery — PE pocket (ARCH-00240) + RQC (ARCH-00320)
= oversight; PROVISIONAL-ACTIVE + PARK-BY-DEMAND + queue = "provisional, not final"; threshold (CS-THRESHOLD-001) +
SWIFT = risk assessment; learning-registry = the loop; Governor decree = ratification. The one genuinely-new piece
was the durable ledger — now built (dna/archive/archive-ledger.yaml, executes BP-0008).

**Opus expert caveats (kept on record):** (a) the DEFAULT floor is non-negotiable — a pure "AI decides each conflict"
reintroduces AI's own instability; (b) self-evolution must PROPOSE, never enact; (c) the VAULT-AND-HALT band must be
reserved for genuinely-hard conflicts or everything stalls. These are the guardrails that make the vision safe.

## 3. TOP-LEVEL-CORESPINE SIGNIFICANCE — the "slippery" question (Governor 2026-07-19)
"Top-level = the one with the most significant tree under it. What is significant — the NUMBER of elements, or the
SIGNIFICANCE in the system?" Governor's method: BUILD several corespines we think are significant; looking at them
reveals the answer (resolve-by-doing). **Opus expert read:** significance = **GOVERNING REACH**, not element count.
A top-level corespine is one whose constraints bind the WIDEST set of descendants (transitive inheritance) + whose
removal breaks ≈everything in its domain ("what breaks if absent?") + which is NOT itself a branch of another domain's
concern. Element-count is a WEAK proxy (a big shallow pile ≠ significant; a small deep root can be). ENDORSE
discover-by-building — but guide each candidate with the reach + "what-breaks-if-absent" test so the top-level set
SURFACES rather than being guessed. This feeds the epistemology-corespine candidate (IBD-0011 §3): does it have the reach?
