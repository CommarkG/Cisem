## THE 7 THINGS WORTH ADOPTING (held my own; the rest is CSP scaffolding, dropped)

### 1. The 3-LAYER doctrine model — L1 sealed / L2 domain / L3 instances  ★ resolves a core CISEM confusion
Separate three things CISEM keeps conflating:
- **L1 (sealed essence):** what the corespine PERMANENTLY means — no examples, no cross-refs, no decomposition; amendable ONLY by ratification. = CISEM's constitutional KERNEL (AI reads, can't edit).
- **L2 (domain decomposition):** how it breaks into governable domains — normal review.
- **L3 (instances):** which artifacts currently instantiate it — updates freely, no amendment.
- **CISEM payoff:** this is the structure for the corespine registry + FOUND-00001. Founding definitions live in sealed L1; the corespine-registry CANDIDATES are L2/L3. It also gives CoreSpiral (just absorbed) its layered home.

### 2. The MECHANICAL attribution chain — declare → validate → propagate
Every artifact declares its corespine in frontmatter; a validator checks (a) the corespine is in the canonical set and (b) its doctrine file exists; missing corespine/anchor = a hard finding. = **the mature form of CISEM's Per-File Alignment Table (ARCH-00401) + the propagation mechanism + tags-as-governance-surface.** CSP proves it's mechanizable. CISEM's version = a plan-audit `[CORESPINE]` check (sibling to `[ROUTING]`/`[ALIGN]`).

### 3. The 3-TYPE node model — Core Spine / Branch / Leaf (structural tests, not vibes)
Core Spine (originates authority; children, no parent) · Branch (derived; parent AND children) · Leaf (terminal). = a clean taxonomy for A2 ("everything is part of a corespine") — replaces vague "corespine vs node" with a testable tree.

### 4. The BRANCH THRESHOLD (T1-T4) + MEG justification  ★ resolves core-vs-instance (§3.2c)
A cluster earns its OWN governance boundary only if ALL: distinct independently-evaluable North Star · ≥N governing nodes an existing corespine can't cover · internal heterogeneity · sibling-uniqueness — AND passes MEG: **"removes more architectural risk than the complexity it adds."** = the mature, testable form of CISEM's core-vs-instance gate + "top-level = governing REACH" (GI-26) + reuse-before-coin/anti-proliferation. This alone is worth the absorption.

### 5. PRECEDENCE ordering — a small canonical set; lower defers  ★ addresses DEC-0006 (still open)
When corespines conflict, a declared precedence order resolves it (lower defers). CISEM's DEC-0006 typed-precedence question has been VAULTED; CSP's ordered-canonical-set is a clean candidate resolution to adapt. (CISEM must derive its OWN ordering — this is the pattern, not the CSP set.)

### 6. PILLARS orthogonal to corespines — A9, mechanized
An artifact declares BOTH a corespine (its governance home) AND pillars (cross-cutting facets). = **exactly A9** (an element is more than one thing — a corespine facet + orthogonal pillar facets, each singly-homed). CSP shows how to mechanize the multi-facet declaration. Also: the **Pillar Protection Line** (an element that invalidates ≥3 others = escalated approval regardless of blast) = a sharp consequence-based tiering for high-blast.

### 7. THE FRAMING — "mis-placed = MIS-GOVERNED, not mis-organized"  ★ the why behind tags-as-governance
A node in the wrong corespine answers to the wrong authority, inherits the wrong blast radius, is measured against the wrong goals — silently, from admission. This is the sharpest possible articulation of WHY A3 + tags-as-the-governance-surface + placement matter. Engrave it.
