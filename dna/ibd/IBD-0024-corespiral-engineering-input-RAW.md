## CSEP 5-phase technical pipeline (validation-gated)
1. **Intake** — boundary-setting + constraint packaging; assign Trace IDs; decompose inputs; query Registry to avoid duplication. Out: Task Manifest (complete constraint package).
2. **Build** — bounded generation; inject Task Manifest as strict context; enhance existing files first, validated vocabulary templates. Out: code + change logs.
3. **Validate** — multi-pass: Pass 1 Structural (schema/naming/coordinates) + Pass 2 Semantic (drift/constitutional compliance). Zero-tolerance for S1/S2 critical. Out: Findings Report + gate decision.
4. **Advance** — memory persistence; update parent/child relationships; track remaining S3/S4 minor debt; commit to version control. Out: updated Registry memory.
5. **Enrich** — self-evolution; analyze Phase-3 failure patterns; programmatically code NEW checks to prevent recurrence in ALL future cycles. Out: enriched Validation Catalog.

## Dynamic Tightening Mechanism
Phase 5 adds newly-learned rules to the Validation Catalog → the environment continually tightens. Cycle 1 runs 5 base checks + adds 2; Cycle 2 inherits all 7 before adding more. As complexity grows the architecture becomes MORE secure — it encodes memory of its own past mistakes as real-time gates.

## Critical Invariant — Cycle Failure Protocol
If Phase-3 validation reports critical anomalies (S1/S2) AND the automated session cannot resolve them after TWO attempts → immediate STOP. Affected files marked `BLOCKED`; tasks moved to an isolated vault; root-cause analysis escalated for manual human review.
