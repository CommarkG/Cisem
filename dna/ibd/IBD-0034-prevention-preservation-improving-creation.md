## Opus draft — A13 candidate (not ratified; GI-63 process required before foundational decree)

**Working title: A13 — Prevention and Preservation by Improving Creation**

**Five-clause draft:**

**Clause 1 — Prevention is class-level, not point-level.** Every error, gap, or defect encountered anywhere in CISEM immediately triggers two acts: (a) a class-level prevention — the standing rule that stops the whole CLASS from recurring — is stated on that same turn; (b) it is routed to both the planning protocol (ARCH-00190) and the creation gate (ARCH-00230) so the next creation self-checks against it. A point-fix that does not also name the class is incomplete (I14 / Principle 17). This is the immune-memory law applied to the creation process itself.

**Clause 2 — Preservation is routed on the same turn discovered.** Every confirmed good — a decision, an insight, a working pattern, a correct outcome — earns an SSOT home on the turn it is confirmed. The route is: SSOT home named → entry added → learning registry updated. "Will be preserved later" is a deferred-and-assumed act (forbidden, Principle 21). Preservation and next-creation-improvement are one unbroken act.

**Clause 3 — Learning loops are the delivery mechanism.** Prevention (Clause 1) and preservation (Clause 2) are inputs to three loops that turn them into structural improvements: (a) the RIPL weekly batch (ARCH-00406) propagates root insights across all four surfaces (planning / implementation / checking / skills); (b) the Weekly Evolution Engine (ARCH-00426) extracts deep patterns across multiple sessions and tunes the default conception itself; (c) the Session Harvest (ARCH-00370, Principle 12) captures each session's fruits at full fidelity before any boundary. Without the loops, prevention and preservation are declarations, not outcomes. The loops ARE the mechanism — document-without-loop is plausibility-completion (Principle 18C).

**Clause 4 — SSOT is the gravitational constant.** Every concept, rule, node, and discovery has ONE authoritative home, and the default motion of the platform is consolidation toward it, not away from it (A8). Any element that is not yet homed is in transit to its SSOT — it is not yet fully captured. New discovery immediately attracts any existing orphans of the same kind and absorbs them. A new element that lands without consolidating pre-existing related content is a fork, not a creation (I19 / I10).

**Clause 5 — New element creation gate.** A new element is authorized ONLY when ALL of the following are true: (i) an explicit Existing-First search (A8/§3.2b) found nothing that can serve or be enhanced; (ii) the element names its SSOT home at birth; (iii) it immediately absorbs any orphaned content of the same kind; (iv) it has reached minimal maturity (a CoreSpiral Cc1 pillar, not a raw idea); (v) a ratified plan authorizes its creation (A4). Any element not passing all five conditions is either an enhancement to something existing or a parked IBD — never a new governed node.

**Why A13 is LEADING (not additive):** A13 provides the OPERATING MECHANISM for A11 (prevention before production) and D3/D4 (prevention is permanent + enhancement is permanent). Those axioms declare the *what*; A13 declares the *how* the platform actually improves itself turn-by-turn. Without the loops and the class-extraction discipline, A11/D3/D4 are aspirational prose. A13 is the engine that makes them structural.
