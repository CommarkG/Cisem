Rules

Invariants I1–I25 — standing prevention rules, each born from a real failure (D3: Prevention is permanent + cumulative). The set only grows; removal needs a foundational decree. Automation state: plan-audit.sh checks I1/I3/I6/I9/I13/I16/I19/I23/I24 (WARN-ONLY; I13 also BLOCKS). SSOT: CISEM-ARCH-00320.

Invariants I1–I25
  • I1
    No phantom references
    Every referenced ID / path resolves on disk OR carries an explicit NOT-YET-A-NODE / example-only tag inline. A dangling reference with no tag is a violation.
    WARN plan-audit.sh
  • I2
    Disclosed ≠ Resolved
    Closure verbs (close / resolve / complete / fix) in a commit or status require a last_verified line + a reproducible check. Acknowledging a problem does not close it.
    MANUAL
  • I3
    Uncommitted truth-bump
    Truth-field changes (Status / RATIFIED / last_verified) commit atomically with a decree reference — never left dangling in the working tree at handoff.
    WARN plan-audit.sh
  • I4
    Registry must have an ID→file manifest
    Every registry maintains an assigned-ID→file manifest, diffable against the filesystem. The manifest is DERIVED (ground truth = registry + filesystem), regenerated and diffed each audit — never hand-authored.
    MANUAL
  • I5
    No dangling children
    Every registry child / dependency reference resolves on disk or is PLACEHOLDER-tagged. A declared child with no file and no tag is a violation.
    MANUAL
  • I6
    Phantom commit claim
    Any "committed / created" claim is verified against git log before the claim is written. A claim that cannot be verified in git history is a violation.
    WARN plan-audit.sh
  • I7
    Truth asserted below Opus
    No truth-bearing field (Status: RATIFIED, last_verified, quality-ledger run entries) authored below the Opus tier. CISEM-ARCH-00300 Hard Line — this is the highest-priority tier invariant.
    MANUAL (tier discipline)
  • I8
    No off-repo authoritative source
    No off-repo artifact (Google Drive, etc.) may be cited as authoritative. It must be migrated into git OR flagged NOT-IN-REPO inline with a named migration step in the active plan.
    MANUAL
  • I9
    Unregistered TYPE prefix
    Every node's TYPE prefix MUST exist in ARCH-00011 §1 TYPE registry, OR the same change updates that registry to add it. A node whose prefix is unregistered is a naming violation.
    WARN plan-audit.sh
  • I10
    SSOT drift / parallel elements
    EVERY concept / element has exactly ONE authoritative source registered in dna/ssot-registry.yaml. Mirrors may summarize / reference but may NOT diverge. A parallel element not obligated to its SSOT is a violation. Broadened 2026-07-18 (A8).
    MANUAL (RQC consolidation audit)
  • I11
    root_authority sprawl
    root_authority: true is confined to the closed set in ARCH-00011 §7 (Founding, ARCH-00011, CS-MASTER-VALIDATION). Adding to the set requires a foundational decree.
    MANUAL
  • I12
    Silent tier-routing
    Every creation / execution DECLARES its tier owner + why before starting (CLAUDE.md §3.0). Opus doing mechanical work needs a stated exception. Silent routing is a violation.
    MANUAL
  • I13
    Core-Seed integrity
    Every [[CORE-SEED]] is Opus-authored and immutable by lower tiers. Must be PRESENT and HONORED in the executed output, verified via a mandatory Seed-Honor Report. A missing, altered, or unhonored seed is a violation.
    BLOCK pre-commit WARN plan-audit.sh
  • I14
    Silent thread-drop / drift
    Every presented decision-item stays OPEN until explicitly resolved / rejected / parked. SILENCE ≠ resolution. On a pivot the reply handles the new AND resurfaces open items. All tiers, all tabs / sessions, no exceptions.
    MANUAL
  • I15
    Category exempt from §3 (A5)
    No category of creation is exempt from §3 gates — files, documents, agents, skills, wizards, vocabulary, file-naming, QC of every type, changes to hardcoded elements, core councils. Creating any of these without the gates is a violation.
    MANUAL
  • I16
    Stale status / dynamic drift
    Every artifact carries ACTIVE governance metadata (tag + status + wiring-state + owner) reflecting CURRENT reality, updated the moment reality changes. A stale or self-contradicting status is a violation. Wiring states: DECLARED → CONNECTED → ACCESSIBLE → LIVE.
    WARN plan-audit.sh
  • I17
    Freestyle governance (no pocket)
    Opus governance / review / rulings run AS the Principal Engineer pocket (ARCH-00240) with a Pocket Declaration stated inline (reasoning_scope, inherited_constraints, output_contract, ai_cannot, recorded_at). Freestyle reasoning outside a declared pocket is a violation.
    MANUAL
  • I18
    Creation Triad incomplete
    Every creation demonstrates ALL THREE as one gate (CLAUDE.md §3.7): hardcoding (§3 + invariants), AI pocket (declared, §3.3 / I17), AI oversight (RQC run + logged to dna/quality-ledger.yaml). Missing any leg is a violation.
    MANUAL
  • I19
    Duplication / no Existing-First search
    Every plan / implement / create is preceded by an EXISTING-FIRST search (CLAUDE.md §3.2b): SSOT-registry → manifest + corespine-registry → archive → grep. A creation that duplicates an existing SSOT concept or re-proposes a ruled-out one is a violation. The search must be stated. Fires on ANY TOPIC CHANGE. Binds Opus + Sonnet, every tab.
    WARN plan-audit.sh
  • I20
    Context boundary without save-all
    Before any compact or tab / session change, the repo MUST be a complete SSOT: continuity record (WITNESS COMPACT STATE) updated, chat-only content embedded to files, everything committed + pushed, handoffs prepped, resume path stated. A boundary crossed without save-all is a violation. Binds Opus + Sonnet.
    CAL pre-compact ENFORCED
  • I21
    Instruction not self-contained (assembly-required)
    Every handed-off instruction (one-click, Core Seeds, handoff, build-prompt) MUST be a SINGLE runnable block: all context + seeds + explicit order INLINE. No "see above", no placeholder, no cross-reference to assemble. The recipient runs it from ONE paste with zero back-reference. Governor-decreed 2026-07-18.
    MANUAL
  • I22
    Unverified done / wired / enforced claim
    Any claim of done / wired / enforced / RATIFIED / COMPLETE MUST cite independently-verifiable evidence: a file path with the ACTUAL mechanism, a commit hash, or shown audit / test output. A "mechanical enforcement" claim requires the mechanism to EXIST and be SHOWN running. Self-attestation is not evidence. All tiers.
    MANUAL
  • I23
    EXISTS ≠ ACTIVE
    No plan stage / capability / claim passes on EXISTENCE alone — it must prove ACTIVATION: the mechanism RUNS, shown, verified by an INDEPENDENT verifier. 4 Wiring States: DECLARED → CONNECTED → ACCESSIBLE → LIVE. Only LIVE counts. Binds all tiers.
    WARN plan-audit.sh + invariant-registry.yaml
  • I24
    Premature status promotion
    A node's claimed STATUS implies a maturity level. Promotion requires that level's validation: RATIFIED needs a decree citation; LIVE needs its mechanism (I23); Validated-Principle needs independent confirmation. A high-status claim without the evidence is premature promotion (DIOS anti-pattern).
    WARN plan-audit.sh + invariant-registry.yaml
  • I25
    Creation without a ratified plan (A4 unenforced)
    A plan is MANDATORY — Governor decree 2026-07-18. NO governed creation (ARCH / protocol / check / agent / skill / axiom / vocab / corespine) may be built without a RATIFIED plan (A4). The ONLY exemptions: IBD raw-capture + SWIFT-safe zero-blast (ARCH-00190 §7). "Small / safe / dogfooding" is NOT an exemption. Binds all tiers.
    MANUAL (ARCH-00392 Phase 0 scope envelopes)
