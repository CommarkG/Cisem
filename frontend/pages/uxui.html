UX/UI Platform DNA

CISEM's UX/UI is platform DNA, not decoration. Two complementary poles — UX (how it feels to think here) and UI (how it's built) — held together (A9 optimal synergy). Switch tabs below; both carry the full toolbar (theme, language, search, Rows/Window view, collapse/expand, Export) — the same abilities as every other tree page in this index.

Core approach to UX
  • −UX ChecklistDRAFT
    • ·1. Zero-wall / progressive disclosure— structure reveals on demand (collapse/expand, toggles); the user controls depth, never a wall of text.
    • ·2. Wide-view-first, drill-down— see the whole, then dive.
    • ·3. Consistency— the same abilities on every surface; learn once.
    • ·4. Honest state— nothing fake; presence≠behavior; every control does exactly what it says.
    • ·5. User owns scope— the platform asks before expanding an action (mirrors the AI wide-view/ask-scope default, IBD-0028).
Core approach to UI — the UI-defaults checklist
  • −UI Defaults ChecklistDRAFT
    • ·1. Dependency-free / offline-first— no CDN, no framework, no build; opens on file://.
    • ·2. Theme-aware via tokens— dark/light, single stylesheet (frontend/css/style.css :root).
    • ·3. Controls on ONE line— the toolbar is a single compact row, not stacked.fixed on schema.html 2026-07-21
    • ·4. WCAG AA contrast minimum— every text ≥ 4.5:1 (normal) / 3:1 (large); MEASURED, never taste-judged.audited 2026-07-21 — see build report
    • ·5. Native links— real <a href> elements, not DOM overlays.
    • ·6. Registry-generated data— never hand-authored (can't go stale).
    • ·7. Single JS file— FE-I2; additive edits, zero collateral deletion.
    • ·8. Behavioral verification— functional-check.mjs asserts a real state change, not "looks wired".
