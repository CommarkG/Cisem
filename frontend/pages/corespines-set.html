Corespines Set

The 5 qualifying criteria for a canonical (L1) corespine, and every corespine currently in corespine-registry.yaml grouped by its ACTUAL registered status. No status here is invented — each badge mirrors the registry field directly. The canonical L1 SET itself is NOT yet finalized (ARCH-00404 Phase 1 — Governor founding call, still open); this page shows the current registry, not a ruling on which entries are permanently canonical.

Canonical (L1) Corespine — the 5 Qualifying Criteria
  • −A corespine earns L1/canonical status only if it passes ALL 5ARCH-00404 + A8 + GI-26
    • ·(a) Governing REACH, not element count— what makes it canonical is what it GOVERNS, not how many files/nodes sit under it (GI-26, "top-level = governing REACH, not element count"; CLAUDE.md §3.2c).
    • ·(b) Passes the Branch Threshold + MEG— earns its own governance boundary only if ALL of {distinct independently-evaluable goal · ≥N governing nodes an existing corespine can't cover · internal heterogeneity · sibling-uniqueness} AND passes MEG: "removes more architectural risk than the complexity it adds" (ARCH-00404 Phase 2).
    • ·(c) Authority-origin (Core Spine node)— in the 3-type node model a Core Spine node ORIGINATES authority (has children, no parent) — distinct from a Branch (derived; parent AND children) or a Leaf (terminal) (ARCH-00404 Phase 2).
    • ·(d) L1-permanent / sealed— sits in the sealed L1 layer: ratification-only amendment, as opposed to L2 (domain decomposition, normal review) or L3 (instances, updates freely) (ARCH-00404 Phase 1, 3-layer doctrine).
    • ·(e) Sole SSOT for its concern— exactly ONE authoritative home for its governed concern; related content consolidates into it, never duplicates or forks (Axiom A8).
