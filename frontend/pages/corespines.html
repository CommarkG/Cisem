Corespines

Governing spines of CISEM — every element belongs to a corespine (Axiom A2). A corespine is a named authority that governs a domain; its invariants, protocols, and artifacts are children of that spine. Creation protocol: ARCH-00394 (Universal Corespine Creation Wizard).

Known Corespines
  • CS-MV
    CS-MASTER-VALIDATION-001 — Root Ratification Authority
    The highest ratification authority in CISEM. All governed creation ultimately chains up to this spine. It confirms that CS-MASTER-VALIDATION-001 is the root of the validation chain and that all ARCH nodes ratified under it are binding. SSOT for the ratification vocabulary.
    RATIFIED
  • CS-AIB
    CS-AI-BEHAVIOR-001 — AI Behavior Governance
    Governs how CISEM's AI tiers behave: tier routing (ARCH-00300), PE pocket definition (ARCH-00240), pocket mechanism, Core Seeds protocol. All agent definition files (.claude/agents/) are children of this spine.
    DECLARED
  • CS-CRE
    CS-CREATION-001 — Creation & Planning Governance
    Governs how every CISEM artifact is planned and created. Children include: ARCH-00190 (planning domain protocol), ARCH-00320 (prevention + plan-audit), ARCH-00392 (context-envelope + governance spine). All plan nodes are children of this spine.
    DECLARED
  • CS-FE
    CS-FRONTEND-001 — Frontend Web Artifacts
    Governs all CISEM frontend web artifacts: this living index, all HTML group pages, the shared CSS + JS. Invariants FE-I1–FE-I10 (single stylesheet, standard nav, breadcrumb arrows, design tokens only, responsive, cell/mobile, dead-link-free, collapsible sections, view toggle). Creation manifest: ARCH-00393. Wizard: ARCH-00394.
    RATIFIED — 2026-07-18
  • CS-TH
    CS-THRESHOLD-001 — Intake Threshold & Routing
    Governs how new inputs are classified and routed: PROCESS-NOW / QUEUE(+build-prompt) / PARK(IBD) / REJECT. Implements the PARK-BY-DEMAND + SWIFT protocol (CLAUDE.md §2.7). Registry entry exists; manifest file not yet built.
    RATIFIED (registry entry — bodiless)
