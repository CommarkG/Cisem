Placement Taxonomy — T-SYS / T-DOM (CISEM-SCHEMA-00001)
  • −T-SYS / T-DOM Trunkstaxonomy root
    • +T-SYSsystem trunk
      • ·Definition— the platform's own operational/structural trunk: corespines, protocols, gates, pipelines. Governs HOW the platform builds itself.
      • ·Rule of thumb— if removing it would break the platform's ability to govern itself, it's T-SYS.
    • +T-DOMdomain trunk
      • ·Definition— domain trunks: Solutions and their content (e.g. SOL-GIFTPRO-001's Product/Supplier/Customer vocabulary, SIMULATION-ONLY). Governs WHAT the platform is used for.
      • ·Rule of thumb— if it only affects one Solution, it's T-DOM.
    • +Missing-ancestor rulebottom-up growth
      • ·Trigger— a new element needs placement and its full T-SYS/T-DOM ancestor chain doesn't exist yet.
      • ·Step 1— auto-generate placeholder nodes for the missing ancestors.
      • ·Step 2— each tagged status: PLACEHOLDER, depth_level: L1.
      • ·Step 3— Goal field: "reserved slot, pending definition".
      • ·Step 4— the triggering element's creation is NOT blocked waiting for the full branch to be designed top-down.
      • ·Precedent— CS-WEB-DESIGN-001 / CS-PHYSICAL-DESIGN-001 (example-only, NOT-YET-A-NODE) established this instinct informally before it was formalized here.
