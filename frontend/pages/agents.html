Agents

CISEM tier workers — Haiku (gather), Sonnet (execute), Opus PE (judge + truth-stamp). Defined in .claude/agents/ and bound via the repo, not session memory. The binding lives in CLAUDE.md §1.5, so any fresh agent tab picks it up immediately.

Tier Overview
claude-haiku-4-5
cisem-haiku
Gathering Tier
Enumerates and gathers evidence only. Runs sweeps and returns raw structured data — never interprets, never judges, never writes governance fields. The fastest, cheapest tier; used for the widest coverage.
grep sweeps ref-scans registry diffs header extraction no judgments no truth-fields
claude-sonnet-4-6
cisem-sonnet
Execution Tier
Executes an Opus-approved plan exactly — applies agreed checklists, drafts from approved outlines, builds manifests, writes code. Honors Core Seeds verbatim and may not edit or remove them. Produces a Seed-Honor Report on every handoff.
execute plans write files run checks honor seeds no ratification no truth-fields (I7)
claude-opus-4-8
cisem-opus-pe
Principal Engineer — Judge Tier
Adversarially verifies lower-tier output (default posture: refute). Makes rulings, writes Core Seeds, stamps truth-bearing fields (Status: RATIFIED, quality-ledger run entries). Operates through the PE pocket (ARCH-00240) with a Pocket Declaration — never freestyle. The ONLY tier that can close a found defect or ratify a node.
rulings ratification truth-fields (I7) Core Seeds quality-ledger writes
Tier Routing Rules (CISEM-ARCH-00300)
  • R1
    Declare before acting
    Every creation / execution DECLARES its tier owner + why before starting (CLAUDE.md §3.0). Silent routing is a violation (I12).
  • R2
    Opus reviews before lower-tier executes
    When a lower tier will execute a plan, Opus MUST review it, code the sensitive parts, and place Core Seeds. The lower tier executes the seeds verbatim and may not edit or remove them (I13).
  • R3
    Opus doing mechanical work = stated exception
    Opus doing low-level mechanical work needs a stated exception (e.g. "trivial, in-context, routing overhead > the work"). Without a stated exception, mechanical work routes to Sonnet.
  • R4
    Binding is repo-based, not session-based
    Tier rules live in CLAUDE.md + the .claude/agents/ files, not in session memory. Any new tab picks up the full binding by bootstrapping from the repo. A tab that has not read CLAUDE.md is unbound and must bootstrap first.
